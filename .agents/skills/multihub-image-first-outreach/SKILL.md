# MultiHub Image-First Outreach | 证据图 × 首联一一对应 v1.0

## Mission & triggers

Use whenever asked "每个首联做图片", "图片链接话术一一对应", "整理客户+首联配图", "精做", "带案例图联系", or to repeat today's image-first prospect outreach process. Convert **existing, source-backed prospect facts** into useful short visual notes, not generic marketing banners. Optimize credible buyer conversations per research hour, not superficial lead or attachment volume.

Read all applicable original rules before authoring. Stricter safety/evidence/contact rule wins.

## Step 0: lock scope, IDs, history, and objective

1. Locate the current original Google Sheet CRM / CONTACT_QA batch, current SOP, prior messages, Case Engine, RECONCILIATION_LEDGER, and per-channel history. Treat entity/company, parent, normalized domain, phone and TG identity as separate dedupe keys. Check **all available** history; explicitly label unresolved coverage.
2. Freeze an ordered batch of **original prospect IDs**. Prior presented/refined prospects retain their original ID; refining them does NOT count as new acquisition. Exclude previously declined, explicitly do-not-contact and historical duplicates from *new first-contact* delivery. Avoid reusing the same image for unrelated companies.
3. Record channel, verified exact URL, whether it reaches a business/decision maker, and recipient role. WA needs an actual official WA link, not a phone number alone. TG must be real person/business contact, never a channel, bot, invite, or group. FB Page ≠ personal/DM route.
4. Separate `CONTACT_QA_HOLD`, `ASSET_DRAFT_READY`, `SEND_READY`, `USER_CONFIRMED_SENT`. **Image completion NEVER grants SEND_READY.** Reject support/order/booking-only routes, unknown human ownership and opt-outs. No automated bulk sends.

## Step 1: pick one real insight per company

For each non-excluded prospect, obtain company site and independent source context; define the specific buyer and one decision question. Review 1–3 official primary pages, plus a directory/review when the insight needs comparison.

Choose exactly one of:
- **A**: verified two-page difference, wording mismatch or clear scope question; show both URLs and distinguish potential package explanations.
- **B**: honestly labelled buyer decision question (scope, ownership, audit, implementation, liquidity, timelines). Do not allege an actual defect unless independently verified.
- **C/HOLD**: insufficient verifiable useful insight. Do not fabricate a flaw or fill quota by drawing fluff.

Store `source_url`, `checked_at`, direct quote/paraphrase, `fact/inference/proposal`, confidence, buyer role, and limitations. A public webpage is NOT a ChatGPT/Gemini answer test. No untested claim of search ranking, lost sales, competitors outranking, increased leads or revenue.

## Step 2: produce a real, honestly labelled mobile image

- Preferred evidence grade `ORIGINAL_CAPTURE`: capture the *actual* source webpage screenshot and raw HTML/text, with UTC capture time and URL, screenshot/hash. Preserve the webpage pixels; callout overlay must not modify source wording. If using actual search/AI tests, retain real recorded session/conditions/results.
- Secondary `TEXT_EVIDENCE_CARD`: a graphic designed from cited public text when an original raw screenshot cannot be captured. **Label visibly or in asset metadata** "Source-backed illustration, not a site screenshot"; no screenshot simulation. This may be delivered as a draft but fails strict v3 original-screenshot gate.
- Consistent MultiHub design: portrait 1080×1350 PNG for WhatsApp/TG, readable on mobile, one company, one headline, 1–2 short fact blocks, one buyer question, one small possible next step, attribution/source URL and date. Use neutral/considerate language, restrained brand styling, no fake company logo, no fabricated chart or badge.
- Save PNG plus evidence original/raw capture (if available), source manifest, full SHA-256 and editing assets. No autogenerated source screenshot from an image model.
- File naming: `<batch_id>__<original_prospect_id>__<company_slug>__evidence.png`. Physical filename, Drive file ID and original ID must all map to exactly one company.

## Step 3: pair message to picture (critical)

For **each** retained ID there must be exactly one primary evidence PNG and **one** selected WhatsApp/TG/FB first-contact draft whose claim is supported by that *same* PNG and source records. No shifted rows, generic mass template, missing link, different company, duplicate image reuse, or stock examples.

- Normally 25–45 English words, hard cap 60; transparent sender identity "I'm with MultiHub" without fake personal name.
- One precise verified fact + visual being attached + **one easy-answer CTA**. Usually only ask for the marketing/website decision maker when contact ownership is unknown. Do not pitch a visibility audit or pretend an AI test passed in the same message.
- **If an image is attached now:** "I attached a quick note showing..." NOT "Can I share the picture?" The CTA should be the relevant human/owner question. **If no actual image is attached:** do not say it is attached.
- Prefer human chat language over pitch decks. No names invented, urgency/fear, blame, exaggerated SEO language, or empty "I am analyzing how buyers search" opener.
- Validate copy against existing geo-outreach-copy policy and local `references/pair-output-contract.md` / `references/qa-checklist.md`. Keep unverified route as `HOLD` even if draft text exists.

## Step 4: transactional link/writeback/dedupe verification

1. Upload image, evidence files and a `pairs.json` / `pairs.md` manifest to a clearly labelled folder inside existing MultiHub Personalized Evidence on Google Drive; do not create a separate untracked root mess.
2. Append (do not overwrite historic IDs) to the original sheet: `image_drive_url` (single click), `first_message` (plain copyable text), `source_urls`, `image_filename`, `image_sha256`, `evidence_type`, `raw_screenshot_status`, `contact_route`, `recipient_role`, `review_status`, `sent_status`. Existing columns may be reused.
3. Read back actual cells + Drive image IDs; validate one-to-one by original ID, no stale old copy, every image link resolves to the intended company. If a verification fails, show explicit exception and HOLD.
4. Append run location, status and dedupe/limitations to `SOP_MASTER` and Gemini master index; mark the same previously presented entity in history once, never duplicate it as a new lead.
5. Keep send and reply flags unchanged until user-provided or authorized platform event proves them.

## Step 5: human delivery — the actual requested experience

Present sequentially for each company, in the exact CRM order:

`Company [original_id] | state HOLD/READY | Image: [clickable PNG] | Message: <literal copyable text> | source link | contact route if VERIFIED | next missing gate`.

Use one block per company. **Never make people cross-reference row N in one list with image N+1 in another**. When many records, additionally deliver a downloadable plain-text or Markdown/CSV pairing pack and its Drive location. If all contacts HOLD, still provide the prepared artifacts, but warn that neither verified delivery route nor sending authorization has been established.

Conclude with audited totals: companies in scope, dedupe exclusions, image-pairs created, original screenshots retained, marketing recipients verified, SEND_READY, sent, replies. Unknown means UNKNOWN, not 0 or inferred.

## Per-run failure rules

- Missing evidence → `IMAGE_PENDING_SOURCE`, not invented.
- Only illustrative text card → `TEXT_EVIDENCE_CARD_HOLD`, never portray as actual page capture.
- Missing valid business/human route → `CONTACT_QA_HOLD`; caption is a draft, NOT executable.
- Historical duplicate/refusal → `HISTORY_LOCK` and exclude from new first-contact.
- Link/file/message one-to-one mismatch → `PAIRING_QA_FAIL`, do not present as complete.
- Never automatically send, log a response, test an AI search platform, or assert payment compatibility without actual evidence.
