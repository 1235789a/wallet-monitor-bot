## Execution order

1. Repair existing IDs from HOLD first. Discover official company websites from independent association, marketplace, registry, trade-show or directory sources; retain source URL and immutable ID. General search may verify, not create source-first provenance. Cheap history comparison before work, authoritative portable private index + live deltas before final clearance.
2. **WA website preflight**, before long company research: fetch home/footer and prioritize linked contact, sales, partnership, quote, team/about pages; max five same-domain pages with bounded timeouts, respect robots and stop on access denial. Capture source page, exact link/label, timestamp and evidence type. Search static hrefs, embedded URLs and labelled public widget data first; then bounded Playwright public DOM rendering and visible QR decode if necessary. Do not navigate to WhatsApp, submit forms or click send. No access circumvention. Follow an official linked social business profile manually only when first-party source corroborates ownership; a directory-only number is not verified.
3. Accept explicit `wa.me`, `api.whatsapp.com/send`, `web.whatsapp.com/send`, valid business short-link/QR, or a number explicitly labelled WhatsApp on the official site. International labelled E.164 number can produce a generated `wa.me` candidate, status `OFFICIAL_LABEL_NUMBER_GENERATED_UNVERIFIED`; ordinary `tel:` stays phone. No guessing country code, no number enumeration; local/ambiguous numbers stay HOLD. A website-published link is a route discovery, not a registered account test or consent. Mark rendered/QR evidence distinctly.
4. Only continue deep research when a route candidate is found. `OFFICIAL_LINK_FOUND`, `LABELLED_NUMBER_REVIEW`, `HOLD_ACCESS`, and `NO_ROUTE_OBSERVED` are preflight states, not READY. If a source fails frequently, switch sources rather than repeat expensive work. Separately review role: founder/owner, business development/partnerships, sales, customer support, bot, unknown. Support/bot-only unsuitable; sales is not automatically a marketing recipient. Keep opt-in and account/recipient confirmation separate. No automatic contact.
5. Verify independent/non-chain ICP (2–20 preferred, max 50), real commercial buyer fit, dated public commercial business activity <=60 days from exact first-party article or attributable public social post, observed excerpt, source URL, reviewed UTC date and confirmed company identity. Freshness rank S+ <=72h, S <=7d, A 8–14d, B 15–30d, C 31–60d. The C tier is still eligible on freshness; all other gates apply. Unverifiable dates/evergreen pages -> HOLD. No WhatsApp last-seen screenshot prerequisite.
6. Dedupe against all authoritative history; missing sources = HOLD_HISTORY. Complete evidence/asset, recipient and explicit opt-in review separately. `wa_account_verified`, `recipient_verified`, `recipient_opt_in_status=VERIFIED` are independent, manual evidence-backed checks. Never infer these fields from preflight. All actual sends remain human-authorized; no auto-send.

## Reusable open-source components

- [Playwright Python](https://github.com/microsoft/playwright-python): render public first-party JavaScript DOM with no login (static fallback if browser unavailable; third-party blocked widgets remain unresolved).
- [python-phonenumbers](https://github.com/daviddrysdale/python-phonenumbers): validate/normalize explicit international phone numbers using libphonenumber; does not verify a WA account.
- [ZXing-C++](https://github.com/zxing-cpp/zxing-cpp): decode public QR screenshot, accept only valid WA business link shapes; no QR login or private session scanning.

Install at repo root: `python -m pip install -r requirements-wa-preflight.txt`; if no Chromium installed, `python -m playwright install chromium` in a supported permitted environment. Static mode: `python scripts/run_wa_website_preflight.py input.json output.json --static-only --per-source 20`. Render mode: omit `--static-only`. The input is an array of source-backed records with `original_prospect_id`, `company_name`, `website_url`, `discovery_source_url`; never use invented sites. Output stays private and includes per-source counts. The script performs no status probes or sends. Browser access/permission errors become HOLD with exact reason.

For WA activity proof supply `--wa-activity-manifest` to `scripts/run_daily27_pipeline.py` (JSON `{ "records": [{ "original_prospect_id": "existing-id", "business_activity_proof": {"source_url": "exact article URL", "activity_date": "YYYY-MM-DD", "checked_at_utc": "ISO UTC review timestamp", "excerpt": "observed commercial content", "subject_type": "COMPANY", "subject_confirmed": true} }] }`). This imports facts, not PASS. The gate rechecks date, review, subject, source and optional capture/hash; a 61-day or undated source stays HOLD.
